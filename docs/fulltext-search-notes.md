# 書架内全文検索（C3）— 设计决策记录

日期：2026-08-14

## 需求

> 全文搜索：先抽样评估 IndexedDB 索引体积，再决定；不能首屏加载 11,041 本全文。（YOMU_PHASE2_GOAL §四）

## 抽样评估（实测数字）

- `data/novels/` 实际收录 **11,041** 本作品 JSON，合计 **573,272KB（约 560MB）**。
  - 平均 51.9KB/本，最大 2,659KB（`2012_ruby_7800.json`），最小 0KB。
- 若为全部作品建全文索引（词 → 位置表），即使按原文 0.5 倍的极乐观压缩比，
  索引体积也在 **280MB 量级**；任何形式的「全库预索引」在手机 WebView 的
  存储配额与首屏时间约束下都不可行。
- 结论：**否决全库索引方案**，不做 IndexedDB 全库索引。

## 采用方案：本地范围 + 查询时扫描

- **范围**：仅「本地已有内容」的书 —— 已下载（`downloaded_books`，IndexedDB）、
  本地导入（`syncedBooks`，IndexedDB）、以及精选书单（`data/books.json`，20 本，
  内容按需 `data/novels/*.json` 拉取后由 SW 缓存）。
- **零额外存储**：不建任何索引文件；查询时把候选书的段落展平（与 reader 相同的
  全局段序：章标题占一位）做子串扫描。
- **不阻塞**：标题/作者过滤先行渲染（同步）；全文扫描异步追加（350ms 防抖），
  结果卡片带「本文一致」标签与摘录，点击跳转到该段落（`openBook(id, true, paraIndex)`，
  优先于已存进度，命中段短暂高亮 `search-hit-flash`）。
- 每本书最多报告 2 个命中段、整体最多 12 本，控制首响应耗时。

## 上限说明（诚实边界）

- 未下载的书库作品**不参与**全文搜索——内容不在本地，按需拉 11k 本等于
  全库索引的变体，已否决。用户想搜某本：先从书库下载，之后即纳入范围。
