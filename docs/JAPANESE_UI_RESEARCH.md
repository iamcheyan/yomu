## 2. Yomu 的日式编辑部视觉原则（可执行）

### 2.1 先按 surface 设计，不把阅读器做成后台

- **Reader**：正文是一份连续文档，排版节奏是第一层级；控件只在需要时出现。
- **Shelf / 首页书架**：帮助用户回到正在读的书，并浏览少量近期内容；封面、标题、作者、进度优先。
- **Library / 书库**：帮助用户搜索、筛选和比较大量作品；搜索是主入口，筛选是次级工具。
- 首页与书库可以有不同密度，但都不应采用“每个对象一张管理卡片”的后台构图。

### 2.2 余白（yohaku）是结构，不是空洞装饰

建议把分组关系交给空间、对齐和字号，而不是边框：

- 页面级：移动端左右内边距 `22–26px`；桌面正文列限制在约 `680–720px`，外部空间保持安静。
- 正文级：段落之间使用 `0.8–1.2em` 的纵向节奏；首行缩进约 `1em`，不要给每段加背景或框。
- 章节级：标题前留出明显呼吸空间，标题后留出较小但稳定的引导间距；章节不使用粗黑左栏。
- 列表级：每行通过上下 padding、封面与文字的基线对齐、细进度线分组；不用行框包围。
- 余白应随内容密度变化：空状态可更宽松，书库搜索结果可适度紧凑；不要所有区域统一大留白导致操作困难。

可执行 token 建议（供后续 DESIGN.md 或 CSS token 评审使用）：

```text
--space-page-mobile: 22px–26px
--space-page-desktop: clamp(32px, 5vw, 96px)
--measure-reader: 680px–720px
--space-paragraph: 0.8em–1.2em
--target-touch: >=44px
--rule-alpha: 0.10–0.16
```

### 2.3 排版优先于 chrome

- 正文默认使用可读的日文明朝体；现有 `YomuFonts` 的汉字/假名 unicode-range 分流应保留，不要为了视觉重构替换掉字体系统。
- 控件和元数据可用克制的日文无衬线体，形成“正文/工具”的语义对比；避免全站都用圆体或装饰手写体。
- 正文建议约 `20–22px`、行高 `2.0–2.15` 起步，再由字号设置调节；这与现有 redesign goal 的基线一致。
- 标题用字号、字重和上下留白制造层级；不要依赖黑底白字标签。
- 日文标题不应强行使用过紧的英文字母 tracking；英文小标签可少量增加字距，但正文保持自然。
- 摘要与作者信息要降低对比度而不是缩到难读；移动端正文/主要操作仍应满足可读性和 44px 触控目标。

### 2.4 纸张、墨色、低饱和色

建议从已有目标中的纸张主题开始，做成有限 token 系统：

```text
纸张背景   #F7F3EA
墨色正文   #282521
次级墨色   #8D867C
低对比线   rgba(40,37,33,.12)
强调色     低饱和茶色 / 赭色 / 灰蓝，单一主色
深夜背景   #141414
深夜正文   #D8D2C8
深夜次级   #858078
```

执行规则：

1. 每个视图最多一个主要强调色；下载、已读、错误状态可以使用少量语义色，但不扩展成彩色标签墙。
2. `#000` 只在极少数需要强焦点的状态使用；常态正文使用暖黑，降低屏幕刺眼感。
3. 纸张不是纹理贴图。先使用纯色和排版建立阅读感，避免噪点背景、和风图案、灯笼/刷子等“日式装饰符号”。
4. 规则线只用于确有必要的分隔或进度，透明度低；不要用 2–3px 黑线同时包围标题、卡片、按钮和弹层。
5. 阴影只用于浮层和抽屉与正文的分离，不能用厚重偏移阴影制造“印刷卡片”。
6. 深色主题也保持纸张/墨色关系：不是纯黑背景加纯白字，而是低刺激的深灰与暖灰。

## 3. 三个核心页面的版式建议

### 3.1 首页书籍列表（Shelf）

**构图**：内容优先的书架，不是统计仪表板。

1. 顶部：`書架` 大标题 + 一句很短的说明；搜索胶囊是唯一显著工具入口。
2. “继续阅读”：有阅读记录时作为横向可滑动但不强制左右分页的轻量区域；每项为封面、书名、作者、进度。它是“回到内容”的快捷入口，不是轮播组件。
3. 主列表：纵向编辑部列表行：小封面 + 书名/作者/摘要或分类 + 细进度线 + 低调的更多操作。点击整行打开，更多按钮触发下载/删除/标记等菜单。
4. 新着、译文、离线等状态使用小点、短文本或低饱和标记，避免多个胶囊 badge 竞争。
5. 空状态使用大留白、一个线性图标、短句和单一操作，不要空状态卡片。
6. 搜索结果与最近书籍共享行结构，避免搜索后突然变成另一套后台卡片。

### 3.2 书库（Library）

**构图**：搜索与比较优先的轻量目录。

1. 标题“書庫”与结果数量/当前筛选状态放在同一信息层，文字淡而清楚。
2. 搜索框是主入口；筛选按钮打开抽屉或 popover，默认不占用首屏高度。
3. 桌面提供列表/网格切换：列表适合作者、分类、可用性比较；网格只用于封面浏览。两种模式共享同一信息层级。
4. 桌面宽屏可以使用左侧索引/筛选栏或 2–3 个宽松列，但列间依靠留白，避免每列都成为卡片墙。
5. 手机默认单列书目行；只有在“封面探索”确实重要时提供两列小封面模式，不能把桌面卡片等比例压窄。
6. 下载状态用细点、图标或“手元にあり”短文本；不可用作品要诚实说明原因，不只显示灰化按钮。
7. 加载使用低对比骨架或少量占位行；筛选为空时保持页面骨架和搜索入口，不显示一堆边框方框。

### 3.3 连续纵向阅读器（Reader）

**构图**：一份出版物/文档，不是分页器。

1. 正文使用正常 document flow，默认只允许纵向滚动；验收 `scrollWidth === clientWidth`。
2. 桌面正文列约 680–720px 居中；两侧空白可作为阅读呼吸，不要用左右栏塞工具。
3. 手机正文左右 22–26px，字号约 20–22px，行高 2.0–2.15；顶部安全区要兼容 WebView safe-area。
4. 书名/作者是安静的 masthead；前言/作者信息使用自然的标题、说明和行间距，去掉黑色标签和网格线。
5. 章节标题通过字号、明朝体、上下 margin 表达；禁止厚重左边框、黑底标签。
6. 进度采用顶部 1–2px 细线和必要时底部轻量文字；进度计算使用 scrollTop/scrollHeight。
7. 顶部 controls 默认隐藏，中央点按呼出；返回、目录、设置、词卡等保留，但不常驻遮挡正文。
8. 目录可以是从右侧/底部出现的抽屉，但它是临时工具，不是阅读页的固定左右分栏。
9. 字体、字号、行距、纸张和亮度是阅读设置的核心操作，应比装饰性按钮更容易找到。

## 6. 三个真正不同的设计方向

### 方向 A：安静编辑部（推荐）

- **核心构图**：Shelf / Library 以无框纵向列表为主；Reader 是中心单列连续文档。
- **视觉**：纸张背景、暖黑正文、低饱和茶色一个强调色；明朝正文 + 无衬线控件；边界主要靠余白。
- **首页**：顶部标题/说明/搜索，继续阅读横向区域，下面是编辑部式列表；桌面右侧放最近阅读或轻量统计。
- **书库**：搜索工具栏 + 列表/网格切换；桌面侧栏可折叠，手机 popover。
- **优点**：最贴合现有 `YOMU_REDESIGN_GOAL.md`、阅读产品属性和日式编辑部语义；改动可围绕已有 DOM/功能渐进收敛。
- **代价**：无框设计需要依靠对齐、间距和 hover/focus 状态解决可发现性；必须认真做可访问性和空/错状态。

### 方向 B：文库目录（Documentary Library）

- **核心构图**：首页与书库更像一份可检索的文学目录；封面缩小，标题/作者/分类/年代等文字占主位。
- **视觉**：更高密度、近白纸色与深灰墨色；使用极少量细横线作为目录节奏；Reader 仍保持宽松单列。
- **首页**：最近阅读作为置顶目录条目；主区按最近/作者/分类分段，使用文字索引和首字母/假名索引。
- **书库**：桌面主区 + 左侧分类索引；手机将索引变为可展开抽屉。
- **优点**：适合青空文库的大目录规模，搜索、作者、分类比较效率高；比卡片网格更能承载大量条目。
- **代价**：封面存在感下降；新用户可能觉得工具性更强、情绪更冷；需要确保移动端目录密度不压迫。

### 方向 C：纸上书架（Cover-led Shelf）

- **核心构图**：首页以大封面与少量精选内容建立安静的书架氛围，书库才切换为列表/网格探索。
- **视觉**：更强的纸张层次和封面比例，颜色仍低饱和；允许少量无边界的“纸片”层叠，但禁止阴影卡片墙。
- **首页**：继续阅读是大主视觉区域，下方为横向封面带和简短书目；搜索仍固定可达。
- **书库**：封面探索优先，提供列表切换用于比较。
- **优点**：最能体现“精致电子书 App”，首页记忆点强；适合有封面质量和精选内容的场景。
- **代价**：青空文库目录量大时，首页视觉与实际内容规模可能失衡；封面缺失/质量不一时需要退化到方向 A 的列表；不要把横向封面带误做成左右分页阅读器。

### 方向比较

| 维度 | A 安静编辑部 | B 文库目录 | C 纸上书架 |
|---|---:|---:|---:|
| 连续阅读一致性 | 很强 | 很强 | 很强 |
| 大目录搜索/比较 | 强 | 最强 | 中 |
| 首页内容氛围 | 强 | 中 | 最强 |
| 对现有结构的渐进兼容 | 最强 | 强 | 中 |
| 卡片墙风险 | 低 | 最低 | 中（封面带需克制） |
| 推荐度 | **首选** | 次选 | 实验方向 |

## 7. 推荐决策与实施边界

推荐 **方向 A：安静编辑部**，原因不是它“最日式”，而是它同时满足：

1. Yomu 的产品核心是阅读，不是目录管理；Reader 可以把注意力还给正文。
2. 现有页面结构已经有 `home-hero`、`home-searchbar`、`home-continue`、`book-grid`、`store-toolbar`、`reader-page` 等语义骨架，可优先调整布局与 token，不必重写功能模型。
3. 它能把“无框”落实为结构原则：列表用余白和对齐分组，书库用临时筛选，阅读器用文档流，而不是简单把边框颜色改成米色。
4. 它兼容 390px 的单列触控体验和 1280/1920 的主区+侧栏/宽留白体验，避免桌面只是拉宽手机布局。

后续实施时建议按以下顺序（仅为设计/验收边界，不是本次代码任务）：

1. 先锁定 Reader：默认路径只保留纵向 scrollTop/scrollHeight；确认 no horizontal overflow；再处理章节/前言的无框排版。
2. 再统一 token：纸张、墨色、次级墨色、规则 alpha、正文 measure、移动页边距、触控目标；保留字体加载与主题设置。
3. 再重排 Shelf：继续阅读 + 无框书目行 + 搜索；把下载/删除/菜单做成不破坏整行点击的明确操作。
4. 再重排 Library：搜索主入口、筛选抽屉、列表/网格两种密度；用真实数据验证短屏幕与大量结果。
5. 最后做 390/1280/1920 与亮/暗主题的运行时回归，尤其检查 review 中记录过的 overflow、裁切、page size、目录和双 ID 风险。

### 建议的设计验收

- [ ] 390×844：首页、书库、阅读器首屏和空/加载/错误状态可完成核心操作。
- [ ] 1280×800：短高度下结果仍可滚动，未被筛选 chrome 或固定 page size 裁切。
- [ ] 1920×1080：正文仍为 680–720px 单列；页面有编辑部层级而非全宽卡片墙。
- [ ] Reader：`scrollWidth === clientWidth`，无左右分页、箭头、横向阅读容器；进度由纵向滚动驱动。
- [ ] Shelf / Library：搜索、打开、下载、进度、离线状态、筛选、排序、懒加载和重试仍可用。
- [ ] 视觉：默认不出现厚重黑线、黑色标签块、每项边框、装饰性渐变、玻璃拟态或多色 badge 墙。
- [ ] 可访问性：主要文本对比度、键盘 focus、触控目标 >=44px、抽屉/弹层关闭和屏幕阅读器标签均需验证。
- [ ] 亮/暗主题与现有四档护眼背景保持同一层级逻辑；字体分流和离线字体加载不回归。

## 结论

Yomu 最适合的不是“加一些日本风格装饰”，而是把界面从组件容器改成出版物结构：**纸张作为连续背景，墨色作为连续文字层级，余白负责分组，正文负责占据视觉中心，控件退到需要时才出现**。在三个方向中，推荐“安静编辑部”；它能在不牺牲搜索、下载、进度和离线能力的前提下，最直接地解决线条框框、后台卡片墙和左右分页三类核心问题。
